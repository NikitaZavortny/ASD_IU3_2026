## Структура

Одна задача — один самостоятельный класс в отдельном файле. Ввод, вывод,
проверки и алгоритм находятся в этом же классе. Общих вспомогательных классов нет.
Для каждой задачи есть отдельный класс тестов. Задача 60 с BFS удалена.

## Идеи решений

1. **Минимум и максимум (MinMax).** Сохраняем первый элемент как оба экстремума.
   За один проход обновляем минимум и максимум. Возвращаем int[2], исходный массив
   сохраняется. Проверяем ограничение 1 < n < 100000. Время Θ(n), дополнительная память Θ(1).
2. **Пузырьковая сортировка (BubbleSort).** Сравниваем соседние элементы и меняем их
   местами, когда левый больше правого. После прохода сокращаем рабочую часть массива.
   Если обменов не было, завершаем сортировку. Сортируем на месте, счётчик long.
   Время Θ(n) в лучшем случае, Θ(n²) в среднем и худшем; дополнительная память Θ(1).
3. **Спираль (SpiralTraversal).** Обходим верхнюю, правую, нижнюю и левую стороны
   текущего слоя, затем сдвигаем четыре границы внутрь. Отдельно учитываем совпадение
   сторон, когда осталась одна строка или один столбец. Используем только массивы
   и индексы. Время Θ(nm), память результата Θ(nm), сверх результата Θ(1).
4. **Змейка (SnakeMatrix).** Последовательно записываем числа от 1 до nm.
   В чётных строках идём слева направо, в нечётных — справа налево.
   Время Θ(nm), память результата Θ(nm).
5. **Определитель (Determinant3x3).** Используем разложение по первой строке.
   Миноры вычисляем в long, итоговые произведения — в BigInteger, чтобы избежать
   переполнения. Вход — матрица 3 × 3 из int. Время и память Θ(1).

Оценки для матриц приведены при положительных размерах. Полные расчёты, оценки
для пустых матриц и различие между полной и дополнительной памятью — в complexity.md.
В новых алгоритмах используются только массивы и простые переменные.
BigInteger из стандартной библиотеки остаётся только в задаче 59.

## Автоматическая проверка

JUnit 5 проверяет обычные и граничные случаи, сохранение входа там, где это обещано,
отклонение некорректных размеров и формат консольного вывода. Для пузырьковой сортировки
на 100 случайных массивах отдельно сравниваются число обменов с числом инверсий и результат
с Arrays.sort. Arrays.sort используется только в тесте как независимый эталон.

Команда mvn clean test запускает Spotless, Checkstyle, тесты и JaCoCo.
Порог покрытия строк и ветвей — 80%, исключений классов нет.
Фактический результат текущей версии приведён в validation.md.
