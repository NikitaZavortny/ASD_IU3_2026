# Отчёт: задача 15. Пузырьковая сортировка с подсчётом обменов

ФИО: Заворотний Н. И.  
Группа: ИУ3-33Б  
Номер лабораторной: 1

## Постановка задачи

Ввод: число `n ≥ 0`, затем `n` целых чисел типа `int`.
Вывод: отсортированный массив в первой строке и количество обменов во второй.

## Структура

Решение оформлено одним самостоятельным классом `BubbleSort` в файле `BubbleSort.java`.
Ввод, вывод, проверки и алгоритм находятся внутри этого класса.
Для проверки используется отдельный класс `BubbleSortTest` в файле `BubbleSortTest.java`.

## Идея решения

Сравниваем соседние элементы и меняем их местами, если левый больше правого.
После каждого прохода наибольший элемент рабочей части оказывается в её конце,
поэтому следующий проход становится короче.

Переменная `changed` показывает, был ли хотя бы один обмен. Если обменов не было,
массив уже отсортирован и алгоритм завершается досрочно. Равные элементы не обмениваются.

Данные хранятся в `int[]`, сортировка выполняется на месте. Для перестановки
используется временная переменная, количество обменов хранится в `long`.

## Анализ асимптотики

В худшем случае число сравнений:
`(n − 1) + (n − 2) + ... + 1 = n(n − 1)/2`, поэтому время — `Θ(n²)`.

Если массив уже отсортирован, выполняется один проход из `n − 1` сравнений:
лучшее время — `Θ(n)` при `n ≥ 2`. Для пустого массива и одного элемента — `Θ(1)`.
Среднее время для равновероятных перестановок различных элементов — `Θ(n²)`.

Каждый обмен соседних элементов устраняет одну строгую инверсию. Поэтому число
обменов равно исходному числу инверсий, максимум — `n(n − 1)/2`.
Для счётчика используется `long`, поскольку этого количества может не вместить `int`.

Новый массив не создаётся: дополнительная память — `Θ(1)`.
Полная память программы с учётом входного массива — `Θ(n)`.

## Ручные тесты

| Вход | Ожидаемый результат | Что проверяет |
| --- | --- | --- |
| n=3; 3 1 2 | 1 2 3; обменов 2 | Сортировка и подсчёт обменов |
| n=4; 4 3 2 1 | 1 2 3 4; обменов 6 | Обратный порядок |
| n=4; 1 2 3 4 | 1 2 3 4; обменов 0 | Отсортированный массив |
| n=4; 3 1 2 1 | 1 1 2 3; обменов 4 | Повторяющиеся элементы |
| n=1; 7 | 7; обменов 0 | Один элемент |
| n=0 | Пустая строка; затем 0 | Пустой массив |

Точка с запятой в таблице разделяет строки матрицы или части результата.

## Автоматическая проверка

Основные тесты JUnit 5:

- `shouldSortMixedValues` — сортировка неупорядоченного массива.
- `shouldCountAllExchangesForReverseOrder` — число обменов при обратном порядке.
- `shouldLeaveSortedArrayWithoutExchanges` — нулевое число обменов для отсортированного массива.
- `shouldNotSwapEqualElements` — равные элементы не обмениваются.
- `shouldMatchInversionCountOnRandomArrays` — сравнение сортировки и числа обменов с независимыми эталонами.

В последнем тесте проверяются 100 случайных массивов с фиксированным seed.
Ожидаемое число обменов находится отдельным подсчётом инверсий, отсортированный
результат сравнивается с `Arrays.sort`. Готовая сортировка используется только
в тесте как эталон. Также проверяются пустой массив, один элемент, границы `int`,
`null`, отрицательная длина и консольный вывод.
